## 东京软银和 IIJ，选哪条线路

这是买绿云东京最容易踩的分叉口，也是大多数横评文章只写「日本软银/IIJ」四个字就略过去的地方。NodeSeek 2026 年 10 月的实测数据把两条线路的差异说得很具体（测试对象是东京 KVM/存储机型）：

| 项目 | 东京软银 | 东京 IIJ |
| --- | --- | --- |
| IPv4 回程延迟 | 电信 43ms / 联通 94ms / 移动 70ms | 电信 104ms / 联通 104ms / 移动 75ms |
| IPv6 | 绕美 280–395ms，基本不可用 | IIJ 直连，可用 |
| IP 质量 | 被墙风险高，换 IP 收 $2 | 干净，无被墙报告 |
| 流媒体解锁 | ChatGPT/YouTube/TikTok，Netflix 仅自制 | ChatGPT/YouTube/TikTok/Prime，Netflix 仅自制 |
| 系统盘 | NVMe，顺序读 3.1GB/s | NVMe，顺序读 3.1GB/s |

结论不算复杂：**软银延迟低一大截（电信方向 43ms 对 104ms），但 IP 有被墙风险；IIJ 延迟普通，但 IP 干净、IPv6 能用、库存也更稳**。如果你的用途是建站或跑服务，IP 被墙等于这台机器对国内直接失效，IIJ 更稳；如果是自用低延迟节点、能接受换 IP 的 $2 成本，软银的 43ms 体验明显更好。

两个细节数据点：存储系列的线路表现和 KVM 不完全一样——digvps 实测软银款走 SoftBank 回程（电信 163/联通 CMI/移动 4837），IIJ 款三网都走 IIJ，电信方向评价比较差，所以买存储机同样优先考虑软银款。早期评测也提过绿云日本机房电信、联通回程直连、移动绕港，和这次实测的移动 70–75ms 基本对得上。另外 VPSIUM 收录的用户反馈提到，东京线路质量不太稳定，有人分到软银、也有人遇到绕路，下单前先看 Looking Glass、到手尽快测路由是必要动作。

社区实测还有个值得记住的细节：宣传 CPU 与实际到手型号经常对不上（比如软银节点到手是 Xeon Platinum 8255C 而非活动页标称的配置），GB5 多核在 2400–3500 区间，性能本身不差，但买这类低价机要把「配置以到手实测为准」当默认预期。

坦白说，绿云东京不适用所有「便宜日本vps」的搜索者。按情况分：

- **要求 IP 长期稳定、跑正经业务**：IIJ 更稳，或者预算上浮看 DMIT、搬瓦工这类 CN2 GIA 精品线。
